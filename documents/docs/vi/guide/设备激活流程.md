# Quy trình kích hoạt thiết bị

## Tổng quan

Quy trình kích hoạt thiết bị chịu trách nhiệm xác thực danh tính thiết bị và tải các thông tin cấu hình cần thiết. Hệ thống hỗ trợ hai giao thức kích hoạt v1 và v2, trong đó giao thức v2 sử dụng cơ chế xác thực bảo mật dựa trên HMAC-SHA256.

## Các giai đoạn khởi tạo hệ thống

### Phân chia giai đoạn

Quá trình khởi tạo hệ thống được chia thành ba giai đoạn chính:

1. **Giai đoạn dấu vân tay thiết bị**: Chuẩn bị thông tin định danh thiết bị
2. **Giai đoạn quản lý cấu hình**: Khởi tạo trình quản lý cấu hình
3. **Giai đoạn cấu hình OTA**: Lấy thông tin cấu hình từ máy chủ

### Giai đoạn 1: Dấu vân tay thiết bị

Thu thập và quản lý thông tin định danh thiết bị thông qua lớp `DeviceFingerprint`:

- Tạo hoặc tải số sê-ri thiết bị (Serial Number)
- Tạo hoặc lấy khóa HMAC
- Quản lý trạng thái kích hoạt cục bộ
- Lấy địa chỉ MAC đã chuẩn hóa

Tệp dấu vân tay thiết bị được lưu tại `config/efuse.json`, bao gồm:
```json
{
  "serial_number": "SN-xxxxxxxxxxxxxxxx",
  "hmac_key": "Chuỗi thập lục phân 64 ký tự",
  "mac_address": "xx:xx:xx:xx:xx:xx",
  "activated": false
}
```

### Giai đoạn 2: Quản lý cấu hình

Khởi tạo trình quản lý cấu hình và đảm bảo các mục cấu hình trọng yếu:

- Khởi tạo `CLIENT_ID` (định dạng UUID)
- Thiết lập `DEVICE_ID` (địa chỉ MAC) từ dấu vân tay thiết bị
- Xác minh tính toàn vẹn của cấu hình

### Giai đoạn 3: Cấu hình OTA

Gửi yêu cầu lấy thông tin cấu hình tới máy chủ OTA:

**URL yêu cầu**: `SYSTEM_OPTIONS.NETWORK.OTA_VERSION_URL`

**Header yêu cầu**:
```
Device-Id: Địa chỉ MAC
Client-Id: UUID của client
Content-Type: application/json
User-Agent: board_type/app_name-version
Accept-Language: zh-CN
Activation-Version: version (chỉ dùng cho giao thức v2)
```

**Body yêu cầu**:
```json
{
  "application": {
    "version": "Phiên bản ứng dụng",
    "elf_sha256": "Khóa HMAC"
  },
  "board": {
    "type": "Loại thiết bị",
    "name": "Tên ứng dụng",
    "ip": "IP cục bộ",
    "mac": "Địa chỉ MAC"
  }
}
```

## Phân tích trạng thái kích hoạt

Hệ thống phân tích trạng thái dựa trên trạng thái kích hoạt cục bộ và phản hồi từ máy chủ:

### Xử lý các tổ hợp trạng thái

1. **Cục bộ chưa kích hoạt + Máy chủ trả về dữ liệu kích hoạt**: Cần thực hiện quy trình kích hoạt
2. **Cục bộ đã kích hoạt + Máy chủ không trả về dữ liệu kích hoạt**: Thiết bị đã được kích hoạt
3. **Cục bộ chưa kích hoạt + Máy chủ không trả về dữ liệu kích hoạt**: Tự động sửa lại trạng thái cục bộ
4. **Cục bộ đã kích hoạt + Máy chủ trả về dữ liệu kích hoạt**: Trạng thái không nhất quán, có thể cần kích hoạt lại

### Định dạng phản hồi của máy chủ

Phản hồi khi lấy cấu hình thành công:
```json
{
  "mqtt": {
    "endpoint": "Địa chỉ máy chủ MQTT",
    "client_id": "ID client MQTT",
    "username": "Tên đăng nhập",
    "password": "Mật khẩu",
    "publish_topic": "Topic xuất bản"
  },
  "websocket": {
    "url": "URL máy chủ WebSocket",
    "token": "Token truy cập"
  }
}
```

Phản hồi khi cần kích hoạt:
```json
{
  "activation": {
    "message": "Thông báo hướng dẫn kích hoạt",
    "code": "Mã xác minh gồm 6 chữ số",
    "challenge": "Chuỗi ngẫu nhiên dùng cho chữ ký HMAC",
    "timeout_ms": 30000
  }
}
```

## Quy trình kích hoạt giao thức v2

### Điều kiện kích hoạt

Khi hệ thống phân tích và xác định cần kích hoạt, quy trình kích hoạt sẽ được bắt đầu:

1. Kiểm tra số sê-ri thiết bị và khóa HMAC
2. Hiển thị mã xác minh cho người dùng
3. Phát thông báo bằng giọng nói
4. Thực hiện xác thực chữ ký HMAC

### Tính toán chữ ký HMAC

Sử dụng thuật toán HMAC-SHA256 để ký chuỗi `challenge`:
```python
signature = hmac.new(
    hmac_key.encode('utf-8'),
    challenge.encode('utf-8'),
    hashlib.sha256
).hexdigest()
```

### Yêu cầu kích hoạt

**URL yêu cầu**: `OTA_VERSION_URL + "activate"`

**Header yêu cầu**:
```
Activation-Version: 2
Device-Id: Địa chỉ MAC
Client-Id: UUID của client
Content-Type: application/json
```

**Body yêu cầu**:
```json
{
  "Payload": {
    "algorithm": "hmac-sha256",
    "serial_number": "Số sê-ri thiết bị",
    "challenge": "Challenge từ máy chủ",
    "hmac": "Chữ ký HMAC"
  }
}
```

### Xử lý phản hồi

- **HTTP 200**: Kích hoạt thành công, cập nhật trạng thái kích hoạt cục bộ
- **HTTP 202**: Đang chờ người dùng nhập mã xác minh, tiếp tục thăm dò (polling)
- **HTTP 4xx**: Kích hoạt thất bại, ghi lại thông tin lỗi

### Cơ chế thử lại

Yêu cầu kích hoạt áp dụng cơ chế thăm dò dài (long polling):

- Số lần thử lại tối đa: 60 lần
- Khoảng cách giữa các lần thử: 5 giây
- Tổng thời gian chờ tối đa: 5 phút
- Mỗi lần thử lại sẽ phát lại thông báo đọc mã xác minh

## Tích hợp giao diện người dùng

### Chế độ GUI

Cung cấp giao diện đồ họa thông qua lớp `ActivationWindow`:

- Hiển thị mã xác minh
- Cung cấp phản hồi trạng thái kích hoạt
- Hỗ trợ hủy thao tác kích hoạt
- Chờ bất đồng bộ cho đến khi kích hoạt hoàn tất

### Chế độ CLI

Cung cấp giao diện dòng lệnh thông qua lớp `CLIActivation`:

- Xuất mã xác minh ra cửa sổ dòng lệnh
- Đọc mã xác minh bằng giọng nói
- Hiển thị tiến độ kích hoạt

## Cơ chế bảo mật

1. **Định danh duy nhất của thiết bị**: Tạo số sê-ri duy nhất dựa trên thông tin phần cứng
2. **Chữ ký HMAC-SHA256**: Ngăn chặn các yêu cầu kích hoạt giả mạo
3. **Xác thực qua mã xác minh**: Người dùng nhập thủ công để xác nhận quyền sở hữu thiết bị
4. **Cơ chế long polling**: Thích ứng tốt với môi trường mạng, tránh gửi yêu cầu quá dày đặc

## Cập nhật cấu hình

Sau khi kích hoạt thành công, hệ thống tự động cập nhật cấu hình:

- Thông tin kết nối MQTT
- Thông tin kết nối WebSocket
- Cờ đánh dấu trạng thái kích hoạt cục bộ

Khi việc cập nhật cấu hình hoàn tất, ứng dụng sẽ tiếp tục quy trình khởi chạy bình thường.
