Hướng dẫn cấu hình ​

Tổng quan hệ thống cấu hình ​

Vị trí tệp cấu hình ​

Tệp cấu hình của py-xiaozhi được lưu trong thư mục dữ liệu người dùng (không nằm ở thư mục gốc của dự án), tuân theo quy chuẩn của từng nền tảng:

Nền tảngThư mục cấu hình
WindowsC:\Users\<tên_người_dùng>\AppData\Local\py-xiaozhi\config\
macOS~/Library/Application Support/py-xiaozhi/config/
Linux~/.local/share/py-xiaozhi/config/
<thư mục dữ liệu người dùng>/
├── config/
│   ├── config.json      # Tệp cấu hình chính (cấu hình khi chạy)
│   └── efuse.json       # Tệp định danh thiết bị (tự động tạo)
├── logs/                # Tệp nhật ký
└── cache/               # Tệp bộ nhớ đệm

Mẹo: Nếu nhà phát triển mở rộng muốn tùy chỉnh tên ứng dụng, chỉ cần sửa APP_NAME trong src/constants/system.py để đổi tên thư mục dữ liệu.

Cấu trúc phân tầng cấu hình ​

  1. Mẫu cấu hình mặc định

    • Vị trí: DEFAULT_CONFIG trong src/utils/config_manager.py
    • Vai trò: Cung cấp các giá trị cấu hình mặc định của hệ thống
    • Mục đích: Làm mẫu tự động sinh tệp cấu hình trong lần chạy đầu tiên

  2. Tệp cấu hình khi chạy

    • Vị trí: <thư mục dữ liệu người dùng>/config/config.json
    • Vai trò: Lưu trữ các cấu hình do người dùng tùy chỉnh
    • Mục đích: Cấu hình thực tế mà hệ thống đọc khi hoạt động

  3. Tệp định danh thiết bị

    • Vị trí: <thư mục dữ liệu người dùng>/config/efuse.json
    • Vai trò: Lưu mã định danh duy nhất và trạng thái kích hoạt của thiết bị
    • Mục đích: Kích hoạt và xác thực danh tính thiết bị

Cách truy cập cấu hình ​

Hệ thống cấu hình hỗ trợ truy cập theo đường dẫn phân tách bằng dấu chấm, giúp dễ dàng đọc và cập nhật các cấu hình lồng nhau:

python
# Ví dụ truy cập cấu hình
from src.utils.config_manager import ConfigManager
from src.utils.config_manager import get_config

config = get_config()  # Điểm vào tiến trình phải gọi initialize_config() trước

# Lấy cấu hình mạng
websocket_url = config.get_config("SYSTEM_OPTIONS.NETWORK.WEBSOCKET_URL")

# Lấy cấu hình từ đánh thức
wake_words = config.get_config("WAKE_WORD_OPTIONS.WAKE_WORDS")

# Cập nhật cấu hình
config.update_config("WAKE_WORD_OPTIONS.USE_WAKE_WORD", True)
config.update_config("CAMERA.VLapi_key", "your_api_key_here")

# Tải lại cấu hình
config.reload_config()

Ngôn ngữ giao diện & chuyển đổi nóng không cần khởi động lại (i18n) ​

py-xiaozhi tích hợp sẵn ba bộ gói ngôn ngữ giao diện gồm 简体中文 (zh_CN), English (en_US) và Tiếng Việt (vi_VN) (nằm tại src/i18n/locales/), hỗ trợ chuyển đổi trực tiếp trong khi chạy mà không cần khởi động lại.

Thứ tự ưu tiên và tự động nhận diện:

  1. Biến môi trường XIAOZHI_LANG (ưu tiên cao nhất): ghi đè tạm thời ngôn ngữ giao diện cho phiên chạy hiện tại mà không làm thay đổi config.json:
bash
XIAOZHI_LANG=en_US python main.py
XIAOZHI_LANG=vi_VN python main.py --mode tui
  1. Cấu hình SYSTEM_OPTIONS.LANGUAGE trong config.json: hỗ trợ các giá trị auto, zh_CN, en_US, vi_VN.
  2. Tự động nhận diện ngôn ngữ hệ thống (khi đặt là auto): đọc tuần tự LC_ALL, LC_MESSAGES, LANG và locale của hệ điều hành; nếu khớp tiếng Trung hoặc tiếng Việt sẽ dùng ngôn ngữ tương ứng, còn các môi trường khác mặc định dùng en_US.

Cách chuyển đổi nóng khi ứng dụng đang chạy:

  • Chế độ GUI: Mở Cài đặt → Hệ thống → Ngôn ngữ hiển thị. Khi đổi lựa chọn trong danh sách thả xuống, cửa sổ chính, hộp thoại cài đặt và menu khay hệ thống sẽ cập nhật xem trước ngay lập tức; nhấn Hủy sẽ tự động khôi phục ngôn ngữ trước đó, nhấn Lưu sẽ ghi cố định vào config.json.
  • Chế độ TUI: Nhấn F2 (hoặc nhập s) để mở Cài đặt → Hệ thống → Ngôn ngữ. Sau khi lưu, bảng điều khiển, thanh trạng thái, gợi ý ô nhập liệu và thanh phím tắt phía dưới sẽ chuyển ngôn ngữ ngay lập tức.
  • Phạm vi áp dụng: Chuyển đổi đa ngôn ngữ chỉ áp dụng cho giao diện người dùng và thông báo tương tác; nhật ký vận hành nội bộ và mô tả công cụ MCP cung cấp cho mô hình ngôn ngữ lớn (LLM) vẫn giữ nguyên.

Đổi cấu hình máy chủ ​

Chuyển sang máy chủ tự triển khai ​

  • Nếu muốn sử dụng máy chủ tự triển khai, chỉ cần sửa địa chỉ API OTA; hệ thống sẽ tự động lấy thông tin kết nối WebSocket từ máy chủ OTA:
  • Thay AUTHORIZATION_URL bằng trang quản trị liên kết thiết bị của bạn (ví dụ như xiaozhi.me); khi nhấn nút mở trang sẽ tự động truy cập địa chỉ này.
json
{
  "SYSTEM_OPTIONS": {
    "NETWORK": {
      "OTA_VERSION_URL": "https://your-server.com/xiaozhi/ota/",
      "AUTHORIZATION_URL": "https://xiaozhi.me/"
    }
  }
}

Cơ chế tự động cập nhật cấu hình ​

Khi khởi động, hệ thống tự động cập nhật cấu hình theo quy trình sau:

  1. Lấy cấu hình OTA: Gửi yêu cầu POST đến OTA_VERSION_URL
  2. Tự động cập nhật cấu hình: Hệ thống tự động cập nhật cấu hình MQTT và WebSocket
  3. Thiết lập kết nối: Sử dụng cấu hình vừa cập nhật để thiết lập kết nối

Vị trí mã nguồn liên quan:

  • Lấy cấu hình OTA: phương thức fetch_and_update_config() trong src/core/ota.py
  • Cập nhật cấu hình: các phương thức update_websocket_config() và update_mqtt_config() trong src/core/ota.py

Giải thích tính năng AEC ​

Khử tiếng vọng (Echo Cancellation)

  • Tích hợp sẵn libs/webrtc_apm (WebRTC Audio Processing), dùng ngay trên cả 3 hệ điều hành mà không cần cấu hình hệ thống
  • Lấy luồng trộn TTS/thông báo/media nền do ứng dụng phát làm tín hiệu tham chiếu (Self far) để triệt tiêu tiếng vọng khỏi tín hiệu micrô
  • Tự động bỏ qua (bypass) nếu khởi tạo bộ xử lý thất bại, không làm gián đoạn việc sử dụng

Lọc nhiễu (Noise Suppression)

  • Giảm tiếng ồn nền và tạp âm môi trường
  • Nâng cao độ chính xác nhận diện giọng nói

Ảnh hưởng đến chế độ hội thoại

json
{
  "AEC_OPTIONS": {
    "ENABLED": true  // Khi bật: chế độ hội thoại thời gian thực (ListeningMode.REALTIME)

  }
}

bash

Cấu hình thiết bị âm thanh (AUDIO_DEVICES) ​

Cài đặt đầu vào/đầu ra âm thanh ​

json
{
  "AUDIO_DEVICES": {
    "input_device_id": null,
    "input_device_name": null,
    "output_device_id": null,
    "output_device_name": null,
    "input_sample_rate": null,
    "output_sample_rate": null,
    "input_channels": 1,
    "output_channels": 2,
    "opus_output_sample_rate": 24000,
    "frame_duration": 20

}

Giải thích mục cấu hình ​

Mục cấu hìnhKiểuMặc địnhMô tả
input_device_idIntegernullID thiết bị đầu vào (tự động nhận diện)
input_device_nameStringnullTên thiết bị đầu vào
output_device_idIntegernullID thiết bị đầu ra (tự động nhận diện)
output_device_nameStringnullTên thiết bị đầu ra
input_sample_rateIntegernullTần số mẫu đầu vào (tự động nhận diện)
output_sample_rateIntegernullTần số mẫu đầu ra (tự động nhận diện)
input_channelsInteger1Số kênh đầu vào
output_channelsInteger2Số kênh đầu ra
opus_output_sample_rateInteger24000Tần số mẫu giải mã Opus: 24000 (chính thức) hoặc 16000 (bên thứ ba)

Giải thích tần số mẫu và độ dài khung ​

Tần số mẫu giải mã Opus

  • 24000: Dùng cho máy chủ chính thức, chất lượng âm thanh tốt hơn
  • 16000: Dùng cho máy chủ bên thứ ba, khả năng tương thích tốt hơn

Lựa chọn độ dài khung

Độ dài khung chủ yếu ảnh hưởng đến tần suất mã hóa đầu vào và callback của thiết bị. Độ dài khung âm thanh trả về từ máy chủ được client tự động nhận diện (bằng cách phân tích byte Opus TOC), không cần khớp thủ công.

  • 20ms: Độ trễ thấp, phù hợp hội thoại thời gian thực (mặc định trên x86)
  • 40ms: Chế độ cân bằng giữa độ trễ và hiệu năng
  • 60ms: Tốn ít CPU, phù hợp cho thiết bị cấu hình hạn chế như Raspberry Pi

Tự động nhận diện thiết bị âm thanh ​

Hệ thống tự động phát hiện các thiết bị âm thanh khả dụng khi khởi động. Nếu cần chỉ định thủ công, bạn có thể cấu hình ID và tên thiết bị:

json
{
  "AUDIO_DEVICES": {
    "input_device_id": 2,
    "input_device_name": "MacBook Air Microphone",
    "output_device_id": 1,
    "output_device_name": "MacBook Air Speakers"
  }
}

Khi chạy, hệ thống ưu tiên khớp theo tên thiết bị (vì ID có thể thay đổi khi cắm/rút thiết bị).

Làm mới thiết bị nóng khi đang chạy (Bluetooth, v.v.) ​

Khi bạn kết nối tai nghe Bluetooth sau khi ứng dụng đã khởi chạy:

  1. Xác nhận trong cài đặt âm thanh của hệ điều hành rằng thiết bị đã kết nối và khả dụng cho đầu vào/đầu ra
  2. Mở Cài đặt → Thiết bị âm thanh → Làm mới thiết bị
    (Thao tác này sẽ tạm ngắt micrô/loa trong giây lát, khởi tạo lại PortAudio và liệt kê lại thiết bị)
  3. Chọn thiết bị mong muốn trong danh sách rồi nhấn Lưu
    → Kích hoạt sự kiện CONFIG_CHANGED, AudioPlugin sẽ gọi reload_devices để chuyển sang thiết bị mới

Nếu làm mới xong vẫn chưa thấy thiết bị: hãy kiểm tra xem hệ điều hành đã cung cấp điểm cuối âm thanh chưa, hoặc thoát ứng dụng rồi "kết nối Bluetooth trước khi khởi động" (liệt kê khi khởi động nguội luôn ổn định nhất).

Triển khai: refresh_portaudio_devices + sự kiện AUDIO_DEVICES_REFRESH_REQUEST.

Chi tiết cấu hình giao thức ​

Cấu hình giao thức WebSocket ​

Thông tin kết nối WebSocket thường được máy chủ OTA cấp phát tự động, không cần cấu hình thủ công:

json
{
  "SYSTEM_OPTIONS": {
    "NETWORK": {
      "WEBSOCKET_URL": "wss://your-server.com/xiaozhi/v1/",
      "WEBSOCKET_ACCESS_TOKEN": "your_access_token"
    }
  }
}

Lưu ý cấu hình:

  • URL phải bắt đầu bằng ws:// hoặc wss://
  • Hỗ trợ địa chỉ IP hoặc tên miền
  • Cổng mặc định là 8000, có thể điều chỉnh theo cấu hình máy chủ
  • Mã truy cập (access token) dùng để xác thực danh tính
  • Thường do máy chủ OTA tự cấu hình, không cần đặt thủ công

Cấu hình giao thức MQTT ​

json
{
  "SYSTEM_OPTIONS": {
    "NETWORK": {
      "MQTT_INFO": {
        "endpoint": "mqtt.server.com",
        "port": 1883,
        "client_id": "xiaozhi_client_001",
        "username": "your_username",
        "password": "your_password",
        "publish_topic": "xiaozhi/commands",
        "subscribe_topic": "xiaozhi/responses",
        "qos": 1,
        "keep_alive": 60
      }
    }
  }
}

Lưu ý cấu hình:

  • endpoint: Địa chỉ máy chủ MQTT
  • port: Thường là 1883 (không mã hóa) hoặc 8883 (mã hóa TLS)
  • client_id: Mã định danh duy nhất của client
  • qos: Mức chất lượng dịch vụ tin nhắn (0–2)
  • keep_alive: Chu kỳ gửi tín hiệu giữ kết nối (giây)

Tùy chỉnh thư mục có thể ghi (Bộ nhớ đệm / Nhật ký / Từ đánh thức / Plugin) ​

Tệp cấu hình vẫn nằm tại config/config.json trong thư mục dữ liệu người dùng (có thể dùng XIAOZHI_DATA_DIR để đổi toàn bộ thư mục gốc dữ liệu; trang cài đặt hiển thị đường dẫn chỉ đọc kèm nút "Mở thư mục").

Thư mục bộ nhớ đệm, nhật ký và từ đánh thức có thể tùy chỉnh thông qua biến môi trường hoặc mục cấu hình PATHS. Sau khi sửa và lưu, ở lần khởi động tiếp theo, hệ thống sẽ sao chép những tệp ở thư mục cũ chưa tồn tại ở thư mục mới sang đường dẫn mới (không xóa thư mục cũ). Dữ liệu lưu trữ riêng của plugin mở rộng được lưu theo ID plugin tại {thư_mục_gốc_dữ_liệu}/mcp_plugins_data/<plugin_id>/.

Mục đíchBiến môi trườngMục cấu hìnhMặc định
Thư mục gốc dữ liệu người dùng (gồm config)XIAOZHI_DATA_DIR—Thư mục dữ liệu hệ thống/py-xiaozhi
Bộ nhớ đệm (Cache)XIAOZHI_CACHE_DIRPATHS.CACHE_DIR{thư_mục_gốc_dữ_liệu}/cache
Nhật ký (Logs)XIAOZHI_LOG_DIRPATHS.LOG_DIR{thư_mục_gốc_dữ_liệu}/logs
Từ đánh thứcXIAOZHI_KEYWORDS_DIRPATHS.KEYWORDS_DIR{thư_mục_gốc_dữ_liệu}/keywords
Gói plugin MCP—MCP_PLUGINS.DIR{thư_mục_gốc_dữ_liệu}/mcp_plugins
Dữ liệu riêng của plugin MCP——{thư_mục_gốc_dữ_liệu}/mcp_plugins_data/<id>

Thứ tự ưu tiên: Biến môi trường > Cấu hình PATHS > Mặc định.

json
"PATHS": {
  "CACHE_DIR": "/Volumes/Data/xiaozhi-cache",
  "LOG_DIR": "/Volumes/Data/xiaozhi-logs",
  "KEYWORDS_DIR": null
}
