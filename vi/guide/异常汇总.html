4. Không tìm thấy thiết bị âm thanh đầu vào/đầu ra mặc định ​

Mô tả lỗi ​

AudioCodec - ERROR - 初始化音频设备失败: [Errno -9996] Invalid input device (no default output device)
AudioCodec - WARNING - 无法初始化音频设备: [Errno -9996] Invalid input device (no default output device)

Giải pháp ​

  1. Windows:

    • Vào Cài đặt âm thanh (Sound Settings) để bật micro và loa.

  2. Linux/macOS:

    sh
    pactl list sources | grep "Name"

  3. Kiểm tra các thiết bị âm thanh khả dụng:

    python
    import pyaudio
p = pyaudio.PyAudio()
for i in range(p.get_device_count()):
    print(f"Thiết bị {i}: {p.get_device_info_by_index(i)['name']}")

  4. Chỉ định thủ công thiết bị âm thanh:

    python
    stream = p.open(format=pyaudio.paInt16, channels=1, rate=16000, input=True, input_device_index=0)

9. PaAlsaStreamComponent_BeginPolling: Assertion 'ret == self->nfds' failed (Lỗi ALSA trên Ubuntu) ​

Mô tả lỗi ​

text
python: src/hostapi/alsa/pa_linux_alsa.c:3641: PaAlsaStreamComponent_BeginPolling: 假设 'ret == self->nfds' 失败。
已放弃 (核心已转储)

Đây là lỗi khởi tạo PortAudio/ALSA thất bại, biểu hiện là chương trình bị thoát đột ngột (crash) khi khởi động luồng âm thanh.

Phân tích nguyên nhân ​

  1. Lỗi cấu hình ALSA hoặc thiếu quyền truy cập thiết bị âm thanh
  2. Xung đột giữa PulseAudio/PipeWire và ALSA
  3. Thiết bị âm thanh hệ thống chưa được cấu hình đúng
  4. Phiên bản thư viện PortAudio không tương thích

Giải pháp ​

Cách 1: Kiểm tra và sửa cấu hình ALSA ​

  1. Kiểm tra thiết bị âm thanh có hoạt động bình thường không

    bash
    # Liệt kê toàn bộ thiết bị âm thanh
arecord -l  # Thiết bị thu âm
aplay -l    # Thiết bị phát âm thanh

    Nếu lệnh xuất ra "no soundcards found", nghĩa là hệ thống chưa nhận diện được thiết bị âm thanh.

  2. Kiểm thử thiết bị âm thanh

    bash
    # Kiểm thử thu âm (nhấn Ctrl+C để dừng)
arecord -f S16_LE -r 16000 -c 1 test.wav

# Kiểm thử phát lại
aplay test.wav

  3. Kiểm tra các công cụ ALSA đã được cài đặt chưa

    bash
    sudo apt-get update
sudo apt-get install -y alsa-utils alsa-base

Cách 2: Sử dụng PulseAudio (khuyến nghị) ​

Việc ALSA truy cập trực tiếp vào thiết bị phần cứng có thể gây lỗi tương thích; khuyến nghị dùng PulseAudio làm máy chủ âm thanh trung gian:

bash
# Cài đặt PulseAudio
sudo apt-get install -y pulseaudio pulseaudio-utils

# Khởi động PulseAudio
pulseaudio --start

# Kiểm tra PulseAudio có đang chạy không
pactl info

# Liệt kê thiết bị âm thanh
pactl list sources | grep "Name"    # Thiết bị đầu vào
pactl list sinks | grep "Name"      # Thiết bị đầu ra

Nếu PulseAudio hoạt động bình thường, sounddevice của Python sẽ tự động sử dụng PulseAudio thay vì truy cập trực tiếp vào ALSA.

Cách 3: Cấu hình ALSA dùng PulseAudio ​

Tạo hoặc chỉnh sửa tệp ~/.asoundrc:

bash
nano ~/.asoundrc

Thêm nội dung sau:

text
pcm.!default {
    type pulse
}

ctl.!default {
    type pulse
}

Sau đó khởi động lại dịch vụ âm thanh:

bash
pulseaudio --kill
pulseaudio --start

Cách 4: Thêm người dùng vào nhóm audio ​

bash
# Thêm người dùng hiện tại vào nhóm audio
sudo usermod -a -G audio $USER

# Đăng nhập lại hệ thống để có hiệu lực, hoặc dùng lệnh sau để áp dụng tạm thời
newgrp audio

# Kiểm tra danh sách nhóm của người dùng
groups

Cách 5: Cài đặt lại PortAudio và sounddevice ​

bash
# Gỡ các thư viện âm thanh Python
pip uninstall sounddevice pyaudio -y

# Cài đặt lại gói phụ thuộc hệ thống
sudo apt-get remove --purge portaudio19-dev libportaudio2
sudo apt-get update
sudo apt-get install -y portaudio19-dev libportaudio2 libasound2-dev

# Cài đặt lại thư viện Python
pip install sounddevice

Cách 6: Kiểm tra và tắt các dịch vụ âm thanh xung đột ​

Trong một số trường hợp, nhiều dịch vụ âm thanh chạy đồng thời có thể gây xung đột:

bash
# Kiểm tra các dịch vụ âm thanh đang chạy
ps aux | grep -E "pulse|pipewire|jack"

# Nếu cả PipeWire và PulseAudio đang chạy cùng lúc, nên chỉ giữ lại một dịch vụ
# Ubuntu 22.04+ mặc định dùng PipeWire và tương thích với PulseAudio thông qua pipewire-pulse

# Kiểm tra trạng thái PipeWire
systemctl --user status pipewire pipewire-pulse

Cách 7: Sử dụng thiết bị âm thanh ảo (chỉ dùng cho kiểm thử) ​

Nếu thiết bị phần cứng gặp sự cố, bạn có thể tạo thiết bị âm thanh ảo để kiểm thử:

bash
# Nạp mô-đun âm thanh ảo
pactl load-module module-null-sink sink_name=virtual_speaker
pactl load-module module-virtual-source source_name=virtual_mic

# Xem các thiết bị ảo
pactl list sources short
pactl list sinks short

Xác minh đã khắc phục ​

Chạy đoạn mã Python sau để kiểm tra thiết bị âm thanh có hoạt động bình thường hay không:

python
import sounddevice as sd

# Liệt kê tất cả thiết bị
print(sd.query_devices())

# Kiểm thử thu âm và phát lại
import numpy as np

# Thu 2 giây âm thanh
print("Recording...")
audio = sd.rec(int(2 * 16000), samplerate=16000, channels=1, dtype=np.int16)
sd.wait()
print("Recording finished")

# Phát lại đoạn âm thanh vừa thu
print("Playing...")
sd.play(audio, samplerate=16000)
sd.wait()
print("Playing finished")

Nếu đoạn mã trên chạy thành công, thiết bị âm thanh đã được cấu hình đúng.

Lưu ý ​

  1. Ubuntu 20.04/22.04 mặc định sử dụng hệ thống âm thanh khác nhau:

    • Ubuntu 20.04: Chủ yếu dùng PulseAudio
    • Ubuntu 22.04+: Dùng PipeWire (tương thích với PulseAudio)

  2. Máy chủ từ xa / không màn hình (headless): Trong môi trường máy chủ không có màn hình, hãy đảm bảo dịch vụ âm thanh đã được khởi động bình thường:

    bash
    # Kiểm tra dịch vụ âm thanh
systemctl --user status pulseaudio

  3. Môi trường Docker/Container: Cần ánh xạ thiết bị âm thanh của máy chủ vào bên trong container:

    bash
    docker run --device /dev/snd ...

  4. Vấn đề phân quyền: Đảm bảo thư mục /dev/snd/ có quyền truy cập phù hợp:

    bash
    ls -l /dev/snd/
